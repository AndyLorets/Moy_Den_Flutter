## 1. Обзор продукта

### 1.1 Суть
«Мой день» — мобильное приложение для ежедневного роста. Помогает не прокрастинировать и двигаться к цели через минимальное трение и максимальную фокусировку.

> **Главный принцип: всегда показывай одно следующее действие с учётом текущего запаса сил пользователя.**

### 1.2 Проблема
- Пользователь видит 20 задач — закрывает приложение
- Мотивация нужна чтобы начать, но приходит только после начала
- Тревога блокирует действие — нет инструмента для выхода из ступора
- Статичные списки не учитывают реальное состояние человека

### 1.3 Решение v2
- **Smart Entry** — контекст по времени суток
- **Система Энергии** — бюджет сил, адаптированный под состояние
- **Матрица Состояний** — активные конфигураторы отображения
- **Focus Mode** — одна задача на весь экран
- **Стрик через якорные задачи P0** — устойчивая дофаминовая петля

### 1.4 Платформы
- Android (основной таргет)
- Web (Flutter Web → GitHub Pages)
- Flutter 3.27+ / Dart 3.6+ / Material 3

## 2. Система Энергии (Action Points)

### 2.1 Концепция
Каждый день пользователь получает запас **Энергии** — ресурс в процентах (%), который обнуляется в начале нового дня. Отображается на Dashboard как **Energy Bar** вместо простого прогресс-бара задач.

Энергия представляет когнитивную и волевую ёмкость. Это визуальный язык, понятный без объяснений.

### 2.2 Параметр задачи — `energyCost`
Каждая задача имеет поле `energyCost` (int, %) — базовый расход энергии до применения множителя состояния.

| Категория задачи | energyCost (базовый) | Примеры |
|---|---|---|
| Механическая (`isMechanical`) | 5–10% | Поза силы, дыхание, чекбокс привычки |
| Обычная задача | 15–20% | Учёба 10 мин, лог дня |
| Глубокая работа (`isDeepWork`) | 25–35% | Код своей игры, разбор страха |
| Рост/Развитие (`isGrowth`) | 20–30% | Новый маршрут, рисование, нетворкинг |

### 2.3 Динамика расхода
Текущее состояние применяет **мультипликатор** к `energyCost` каждой задачи и изменяет доступный лимит энергии (см. раздел 3).

> Если суммарный `energyCost` всех задач превышает лимит — задачи показываются по приоритету: P0 → P1 → P2, пока бюджет не исчерпан.

### 2.4 Energy Bar — UI
- Заменяет простой прогресс-бар задач на Dashboard
- Заполнение = оставшийся запас Энергии
- Цвет: 🟢 зелёный (>60%) → 🟡 жёлтый (30–60%) → 🔴 красный (<30%)
- Подпись: `«Запас сил: 72%»` — без технических терминов

## 3. Матрица Состояний

Состояния — **не информационные плашки**. Каждое состояние активирует `StateConfig` — набор правил для всей системы.

| Состояние | Лимит энергии | Множитель стоимости | Видимые задачи | Спец. протокол |
|---|---|---|---|---|
| Усталость | 40% | ×1.5 | 2 задачи (P0 + легчайшая) | — |
| Тревога | 60% | ×1.2 | Только `isMechanical` | Протокол заземления |
| Обычное | 100% | ×1.0 | Все задачи бюджета | — |
| Воодушевление | 120% | ×0.8 | Все + бонусная `isGrowth` | Бонусная задача |

### 3.1 Усталость
- Лимит энергии: **40%**
- Стоимость задач: **×1.5**
- Показываются только **2 задачи**: самая приоритетная P0 + самая лёгкая из доступных
- Остальные задачи **скрыты** (не удалены)
- Стрик **сохраняется** при выполнении всех P0 — см. раздел 5
- Пользователь не видит скрытые задачи и не чувствует вины

### 3.2 Тревога — Протокол заземления
- Лимит энергии: **60%**
- Видимы только задачи с тегом **`isMechanical`**
- Все таймеры **скрыты**
- Автоматически предлагается дыхание: вдох 4 → задержка 4 → выдох 8
- Сообщение: `«Начни с малого. Ты уже здесь — это достаточно.»`
- Задачи `isDeepWork` и `isGrowth` скрыты

### 3.3 Воодушевление
- Лимит энергии: **120%**
- Стоимость задач: **×0.8**
- Добавляется одна бонусная задача с тегом `isGrowth` из банка задач
- Сообщение: `«Ты в ресурсе. Используй этот момент.»`

### 3.4 Обычное
- Лимит: **100%**, множитель: **×1.0**
- Все задачи, укладывающиеся в бюджет, по приоритету P0 → P1 → P2

## 4. Модель данных задачи (Task)

### 4.1 Структура

```dart
class Task {
  final String id;
  final String title;
  final Phase phase;          // morning | day | evening
  final Priority priority;    // P0 | P1 | P2
  final int energyCost;       // базовый расход в %
  final List<Tag> tags;       // isMechanical | isEssential | isDeepWork | isGrowth
  final String? hint;
  final int? timerMinutes;
  bool isCompleted;
  final bool isCustom;
}
```

### 4.2 Приоритеты

| Приоритет | Роль | Поведение |
|---|---|---|
| **P0 — Якорь** | Обязательный минимум дня | Всегда видима. Выполнение P0 сохраняет стрик. Нельзя скрыть. |
| **P1 — Цель** | Важная задача | Показывается при наличии бюджета. Скрывается в Усталости. |
| **P2 — Бонус** | Дополнительное действие | Показывается при энергии >70%. Скрывается в Усталости и Тревоге. |

### 4.3 Теги

| Тег | Значение | Влияние |
|---|---|---|
| `isMechanical` | Механическое действие | Приоритет при Тревоге. Низкий когнитивный барьер. |
| `isEssential` | Базовая потребность | Никогда не скрывается. Всегда в топе. |
| `isDeepWork` | Глубокая работа | Скрывается при Тревоге. Высокий `energyCost`. |
| `isGrowth` | Рост и развитие | Бонус при Воодушевлении. Скрывается при Усталости. |

### 4.4 Пример задачи (JSON)

```json
{
  "id": "morning_code",
  "title": "10 мин над своей игрой",
  "phase": "morning",
  "priority": "P1",
  "energyCost": 25,
  "tags": ["isDeepWork", "isGrowth"],
  "timerMinutes": 10,
  "hint": "Ты уже успешный разработчик. Просто открой файл."
}
```

## 5. Логика Стриков (Streak)

> **Стрик сохраняется, если выполнены все задачи уровня P0 (якоря).** P1 и P2 на стрик не влияют.

Это критично: в режиме **Усталости** P1/P2 скрыты, но стрик продолжается — дофаминовая петля не рвётся.

| Сценарий | P0 выполнены? | P1/P2 | Стрик |
|---|---|---|---|
| Обычный день | ✓ | ✓ | ▲ +1 |
| Усталость, P1/P2 скрыты | ✓ | скрыты | ▲ +1 |
| Пропущен P0 | ✗ | ✓ | ✗ сброс |
| Ничего не сделано | ✗ | ✗ | ✗ сброс |

- Хранится в SharedPreferences, ключ: `streak`
- При сбросе — поддерживающее сообщение: `«Каждый день — новое начало. Завтра снова.»`

## 6. UX/UI — Экраны

### 6.1 Dashboard
- Дата и день недели в шапке
- Стрик — дней подряд
- **Energy Bar** с цветовой индикацией (заменяет прогресс-бар задач)
- Бейдж текущего состояния
- Карточка «Следующий шаг» — адаптирована под StateConfig

### 6.2 Completion Screen — адаптивные кнопки

| Энергия / Состояние | Кнопка «Ещё одно» | Кнопка «Достаточно» |
|---|---|---|
| Высокая (>60%) | Большая, зелёная (основная) | Маленькая, серая |
| Средняя (30–60%) | Равные по размеру | Равные по размеру |
| Низкая (<30%) / Усталость | Маленькая, серая | Большая, синяя (основная) |

### 6.3 Поддерживающие сообщения (все на русском)

| Ситуация | Сообщение |
|---|---|
| После P0 в Усталости | «Ты сделал главное. Этого достаточно на сегодня.» |
| Сброс стрика | «Каждый день — новое начало. Завтра снова.» |
| Первая задача дня | «Шаг сделан. Остальное — бонус.» |
| Воодушевление + бонус выполнен | «Ты в потоке. Хорошо использовал этот момент.» |
| Тревога + дыхание завершено | «Немного лучше? Это нормально — так и работает.» |

### 6.4 Убранные системные фразы

| Убрано | Заменено на |
|---|---|
| "Your collection has been updated!" | «Данные сохранены.» |
| "Task completed!" | «Ты сделал шаг.» |
| "Streak lost!" | «Каждый день — новое начало. Завтра снова.» |
| "Loading..." | «Загрузка...» |

### 6.5 FAB «Мне тяжело»
Глобальная кнопка, доступна с любого экрана. Открывает bottom sheet:
- Дыхание: вдох 4 → задержка 4 → выдох 8
- Одна микро-задача (`isMechanical`, минимальный `energyCost`)
- Текст поддержки
- Кнопка «Вернуться к дню»

## 7. Архитектура экранов

| Экран | Назначение |
|---|---|
| `SmartEntryScreen` | Маршрутизация по времени суток + выбор состояния |
| `DashboardScreen` | Energy Bar, стрик, дата, карточка следующего шага |
| `FocusModeScreen` | Одна задача на весь экран |
| `FocusSessionScreen` | Таймер 5–25 мин (скрыт при Тревоге) |
| `CompletionScreen` | Адаптивные кнопки по энергии |
| `OverviewScreen` | Все задачи по фазам, фильтрованные по StateConfig |
| `ScheduleScreen` | Редактируемое расписание |
| `HelpScreen` | Справка: корень проблемы, страхи, техники |
| `SettingsScreen` | Gist, уведомления, сброс дня |

Smart Entry маршрутизация:
- **Утро 5–11:** выбор состояния → StateConfig → одна задача
- **День 11–18:** главное действие по текущей конфигурации
- **Вечер 18+:** итог или одно дополнительное действие

## 8. Хранение данных

### SharedPreferences — ключи v2

| Ключ | Тип | Описание |
|---|---|---|
| `streak` | int | Дней подряд (P0-условие) |
| `last_day` | String | Последний закрытый день |
| `state` | String | Состояние: fatigue / anxiety / normal / excited |
| `energy_limit` | int | Текущий лимит энергии (%) |
| `energy_remaining` | int | Оставшийся запас (%) |
| `t_{taskId}` | bool | Выполнена ли задача |
| `smysl` | String | «Зачем я это делаю» |
| `epoch` | String | Дата начала для учёбы |
| `motiv` | String | Из страха или свободы |
| `fear` | String | Что не сделал из-за страха |
| `insight` | String | Инсайт дня |
| `schedule` | JSON | Расписание |
| `gh_token` | String | GitHub токен |
| `profile` | JSON | Текущий профиль |
| `profiles` | JSON | Все профили |

- Синхронизация вручную или автоматически при каждом изменении
